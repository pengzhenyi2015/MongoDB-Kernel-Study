# 1. 导语

Pre-image 是文档被替换 / 更新 / 删除之前的完整快照，post-image 是文档被插入 / 替换 / 更新之后的完整快照。     

MongoDB 6.0 起，change stream 通过集合级选项 changeStreamPreAndPostImages 支持在事件中携带这两类快照； 7.0 $changeStreamSplitLargeEvent 支持拆分超过 16MB 的事件（对同时携带前后镜像的大文档事件至关重要）；8.0 沿用了 6.0
引入的机制，并在性能与批量写入 oplog 行为上做了改进。

# 2. 用法
## 2.1 为集合开启 pre/post-image 记录（集合级）
```
// 方式一：修改已有集合
db.runCommand({
 collMod: "orders",
 changeStreamPreAndPostImages: { enabled: true }
})
// 方式二：创建集合时指定
db.createCollection("orders", { changeStreamPreAndPostImages: { enabled: true } })
// 验证
db.getCollectionInfos({ name: "orders" })[0].options.changeStreamPreAndPostImages
// => { enabled: true }
```

## 2.2 配置镜像保留策略（集群级，可选）
```
// 显式 TTL：100 秒（整个集群生效）
db.adminCommand({
 setClusterParameter: {
 changeStreamOptions: { preAndPostImages: { expireAfterSeconds: 100 } }
 }
})
// "off" = 跟随 oplog 保留窗口（默认策略）
db.adminCommand({
 setClusterParameter: {
 changeStreamOptions: { preAndPostImages: { expireAfterSeconds: "off" } }
 }
})
// 查看当前配置
db.adminCommand({ getClusterParameter: "changeStreamOptions" })
```

**即使设了 expireAfterSeconds ，只要对应 change stream 事件已被挤出oplog，其 pre/post-image 也会被删除；反过来， expireAfterSeconds: "off" 表示镜像与oplog 事件同生共死。**

## 2.3 打开 change stream 时声明所需镜像
ChangeStream 增加了 2 个参数：
- fullDocumentBeforeChange, 即 pre-image. 对应 update/delete 操作。
- fullDocument，即 post-image. 对应 update/insert 操作。

|选项|取值|行为|
|:--|:--|:--|
|fullDocumentBeforeChange|off （默认）|不返回 pre-image|
||whenAvailable|有则返回，无则该字段为 null|
||required|无 pre-image 时报错（NoMatchingDocument ）|
|fullDocument|default （默认）|update 事件只有 delta|
||updateLookup|事件处理时回查业务集合，返回"更新之后某时刻"的多数派版本（非时间点精确，文档已删则为 null）|
||whenAvailable|返回写入时物化/可合成的时间点精确post-image，不可得为 null|
||required|同上，不可得时报错|

**注意** updateLookup 与 whenAvailable / required是互斥的不同取值，不能组合；并且未开启 changeStreamPreAndPostImages 的集合上设whenAvailable 只能拿到 insert/replace 事件的 post-image（它们本来就存在 oplog 的 o字段里），update 事件的 post-image 拿不到。
